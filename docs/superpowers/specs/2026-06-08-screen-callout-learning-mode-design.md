# screen-callout 학습 모드 설계

작성일: 2026-06-08

## 1. 취지 (왜 만드나)

블렌더처럼 **관심은 생겼지만 기초·기능을 모르는 앱**을, 화면 위에 번호 오버레이를 띄워 놓고
클로드 코드와 **번호로 양방향 대화**하며 익힌다.

- 펼쳐 놓고 → 단축키로 "지금 보는 화면"을 번호로 덮고
- 번호로 묻고(번호→기능), 기능으로도 묻고(기능→번호) 하며 학습·습득
- 잠깐 끄고 직접 만져 보고 → 화면 바뀌면 다시 생성 → 반복

핵심 목표: **클로드 코드가 "번호 토글이 무슨 기능인지"를 효율적이고 정확하게 알아듣고,
정민님이 기능을 말하면 번호로도 답할 수 있어야 한다.**

## 2. 워크플로우

```
블렌더 펼침
  ├─[Option+1]─→ 마우스 있는 모니터를 스캔 → 번호 오버레이 새로 생성
  ├─ "파악해줘" ─→ 클로드가 캡처+콜아웃 읽고 의미 지도(index.json) 작성
  ├─ 번호↔기능 양방향 대화 ──→ index.json으로 즉답
  │     · "47번 뭐야?"        (번호→기능)
  │     · "모델링 관련 몇 번?"  (용도→번호)
  ├─[Option+2]─→ 표시·클릭 일시정지/재개 (직접 만져 보기)
  └─ 화면 바뀌면 다시 [Option+1] … 반복
```

## 3. 확정된 설계 결정

| 결정 | 선택 | 비고 |
|---|---|---|
| 의미 파악 시점 | **스캔 직후 1회 생성** | 물을 때마다 즉석 판단 대신, 미리 의미 지도를 만들어 양방향 즉답·일관 |
| 의미 지도 생성 주체 | **클로드 코드가 직접** | 추가 설치 없음. 대화로 다듬기 가능 |
| 역질의 축 | **용도별 그룹** | 난이도·빈도는 제외(YAGNI). 필요 시 키 한 줄 추가로 확장 |
| 인덱싱 트리거 | "파악해줘" 한마디 | 백그라운드 세션이라 단축키→클로드 자동호출은 불안정 |
| 번호 안정성 | 재스캔마다 새로 매김 | 매번 화면이 달라 번호 유지는 복잡도만 늘어남 |
| 단축키 | Option+1=재생성 / Option+2=토글 | 기존 Option+1(토글)을 Option+2로 이동 |

## 4. 컴포넌트 설계

### 4.1 단축키 2개 + 마우스 화면 타겟팅 (`main.js`)

| 단축키 | 동작 |
|---|---|
| Option+1 (`Alt+1`) | 마우스가 **지금 있는 모니터**를 스캔 → 오버레이 새로 생성 |
| Option+2 (`Alt+2`) | 표시+클릭 일시정지/재개 토글 (기존 `toggleOverlay()` 로직 이동) |

마우스 화면 타겟팅 원리:
```
Option+1
  → main.js: 마우스 커서가 있는 디스플레이 탐지
            (screen.getDisplayNearestPoint(screen.getCursorScreenPoint()))
  → 그 디스플레이 영역만 캡처하도록 scan.sh 호출 (영역 인자 전달)
  → 검출/그룹화 → callouts.json
  → 오버레이 창을 그 디스플레이 bounds로 이동시켜 표시
```
모니터 1개면 그 화면, 듀얼이면 마우스가 있는 쪽이 잡힌다.

Option+1이 스캔을 실행하는 방식: `main.js`가 `child_process`로 `scan.sh`를 spawn한다.
스캔은 1~2분 걸리므로 진행 표시를 둔다(렌더러에 "스캔 중…" 안내). 정확한 표시 방식은 구현 계획에서.

### 4.2 캡처 대상 모니터화 (`scan.sh`)

현재 `screencapture -x` 전체 캡처를, **대상 모니터 영역**으로 한정한다.
`main.js`가 대상 디스플레이의 위치·크기를 인자로 넘기고, `scan.sh`는 그 영역만 캡처한다
(`screencapture -R x,y,w,h` 또는 `-D <num>` 중 안정적인 쪽 — 구현 계획에서 확정).
좌표는 그 화면 기준 0–1 비율이라 Retina 배율과 무관하게 매핑된다.

### 4.3 의미 지도 `index.json` (신규)

스캔 후 클로드가 `now.png`(새 캡처) + `callouts.json`을 읽고, 각 번호에 의미 한 겹을 입힌다.

스키마:
```json
{
  "image": { "width": 0, "height": 0 },
  "app": "Blender",
  "categories": ["파일·씬", "화면·뷰조작", "추가·생성", "변형도구",
                 "모델링", "재질·셰이딩", "애니메이션", "렌더링", "기타"],
  "items": [
    { "n": 47, "label": "Add", "box": {"x":0.10,"y":0.09,"w":0.02,"h":0.01},
      "category": "추가·생성", "desc": "큐브·조명·카메라 등 새 오브젝트를 추가" }
  ]
}
```

- `category`(용도) — "기능→번호" 역질의의 핵심 키. **앱에 맞춰 클로드가 그때그때 용도 묶음을 정한다**
  (블렌더면 블렌더 용도, 포토샵이면 포토샵 용도). 범용 도구이기 때문.
- `desc`(한 줄) — 용도 분류의 부산물로 자연히 생기며, "번호→기능" 즉답에도 그대로 쓰인다.
- 아이콘(라벨 없는 항목)은 기존 `explain.py`의 크롭 기능으로 이미지를 떠서 의미를 확정한 뒤 채운다.
- 개인 화면 내용이 담기므로 `.gitignore`에 추가한다(커밋 금지).

### 4.4 양방향 질의 (클로드가 `index.json`으로 직접)

| 질문 유형 | 동작 |
|---|---|
| "47번 뭐야?" (번호→기능) | `index.json`에서 n=47 찾아 `desc`+`category` 즉답 |
| "추가·생성 관련 몇 번?" (용도→번호) | `category` 필터 → 번호 목록 |
| "모델링 시작하려면 뭐부터?" (의도→번호) | `category`로 추려 동선 안내 |

별도 검출/스크립트 없이 `index.json` 한 파일로 양방향 즉답한다. `index.json`은 대화 기억이
압축돼도 다시 읽어 일관되게 답하는 "외장 기억" 역할도 한다.

## 5. 바뀌는/생기는 파일 (외과적 범위)

| 파일 | 변경 | 내용 |
|---|---|---|
| `main.js` | 수정 | Option+1 재스캔 트리거 / 토글을 Option+2로 / 오버레이를 대상 모니터로 이동 |
| `scan.sh` | 수정 | 캡처 대상을 특정 모니터 영역으로 받도록 인자 추가 |
| `index.json` | 신규 | 의미 지도 (클로드 작성, `.gitignore` 추가) |
| `.gitignore` | 수정 | `index.json` 한 줄 추가 |
| `explain.py` | 변경 없음 | 아이콘 크롭 기능을 인덱싱 때 재사용 |

## 6. 비-목표 (Non-goals)

- 난이도·빈도 자동 태깅 (이번엔 용도별만)
- 번호의 영속적 안정성(재스캔 간 동일 번호 보장)
- 자동 인덱싱(단축키만으로 무인 의미분석) — 별도 VLM/API가 필요해 제외
- 화면 변화 실시간 추적 — 정적 스냅샷 유지(재스캔으로 갱신)

## 7. 검증 방법

- Option+1: 듀얼/단일 모니터 각각에서 마우스 위치에 따라 올바른 화면이 잡히는지 캡처 비교
- Option+2: 토글 전/후/복구 3장 캡처로 표시·클릭 정지 확인 (기존 검증 방식 재사용)
- 의미 지도: 같은 화면에서 "번호→기능"과 "용도→번호"가 서로 모순 없이 답하는지 교차 확인
- 아이콘: 라벨 없는 번호가 크롭을 통해 올바른 의미로 채워지는지 표본 검사
